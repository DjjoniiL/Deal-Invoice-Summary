# Финальный дизайн основного экрана

Этот файл фиксирует утверждённую визуальную версию основного экрана Deal Invoice Summary в левом меню Bitrix24.

## Статус

Дизайн основного экрана утверждён как финальный. Без отдельного подтверждения пользователя нельзя менять:

- `public/menu.css`;
- визуальную композицию `public/index.html`;
- размеры, цвета, отступы, сетку, порядок блоков и внешний вид элементов основного экрана.

Дальнейшие работы должны касаться логики приложения, backend/API, установки, переноса на другой сервер и будущего install-flow. Визуальную часть можно трогать только при явной задаче на изменение дизайна.

## Общая композиция

Основной экран должен помещаться в один экран рабочего Bitrix24 iframe без лишнего вертикального скролла при обычной высоте окна. Интерфейс построен как компактная рабочая панель, а не лендинг.

Порядок блоков:

1. Верхняя плашка приложения с названием, порталом и кнопкой обновления.
2. Компактный блок обращения за доработкой приложения.
3. Две колонки:
   - слева сопоставление полей сделки;
   - справа автопересчёт.
4. Нижний блок ручной проверки сделки.

## Сопоставление Полей

Блок слева содержит только настройки полей сделки:

- выставлено по счетам;
- оплачено по счетам;
- не оплачено по счетам;
- остаток оплаты;
- чекбокс учёта отрицательных стадий;
- кнопку сохранения сопоставления;
- статус сопоставления.

Окно пересчёта в этом блоке больше не показывается.

## Автопересчёт

Блок справа содержит настройки и состояние автоматического пересчёта:

- `Режим расчёта`;
- `Окно пересчёта`;
- интервал;
- пробуждение;
- количество отслеживаемых сделок;
- последний запуск;
- кнопку `Запустить автопересчёт сейчас`;
- шкалу статуса ручного автопрохода.

Режим расчёта:

- `Утром и вечером` — текущий рабочий режим на polling fallback и VibeCode wake schedules;
- `Постоянный` — заготовка под будущие push-события, сейчас выбор этого пункта ничего не активирует.

Окно пересчёта:

- `21 сутки` по умолчанию;
- доступны варианты `42`, `28`, `21`, `14`, `7`, `2` суток.

Шкала статуса появляется только после нажатия `Запустить автопересчёт сейчас`. До запуска она скрыта.

## Карточка Сделки

После сохранения сопоставления приложение пытается добавить в общую раскладку карточки сделки раздел:

```text
Расчёт оплаты счетов
```

В этот раздел встраиваются сопоставленные расчётные поля.

Важно: текущий VibeCode userfields API позволяет выставить `editInList: "N"`, но не даёт отдельного флага для полного запрета редактирования поля в карточке всем пользователям, кроме администраторов портала.

## Файлы

Финальная визуальная часть:

- `public/menu.css` — утверждённый дизайн основного экрана. Не редактировать без отдельного подтверждения.
- `public/index.html` — утверждённая композиция основного экрана. Не менять визуальную структуру без отдельного подтверждения.
- `public/app.js` — можно менять логику, обработчики и API-вызовы, но не менять визуальное поведение без отдельной задачи на дизайн.

Основные будущие зоны работы:

- логика `src/server.js`;
- логика `public/app.js`;
- будущий install-flow;
- перенос приложения на новый сервер/портал;
- OAuth и push-события.

# Next Prompt

Ты работаешь в проекте `G:\AI Project B24\Deal Invoice Summary`.

Это static/serverless Marketplace-приложение Bitrix24 `Deal Invoice Summary`: считает оплату счетов по сделке, пишет расчётные поля сделки, умеет ручной и массовый пересчёт, CSV-отчёт, вкладку сделки, настройки воронки/периода и фоновый `PAGE_BACKGROUND_WORKER`.

Актуальная локальная версия: `Deal Invoice Summary v.36 Marketplace B24`.
Runtime/cache marker: `layout-20260826-2`.
Актуальный zip для загрузки: `Market B24 zip\Расчёт оплат счетов Mini rights Final v.37.zip`.

Ключевое поведение v36:

- worker не вызывает полный `BX24.reloadWindow()`;
- после записи полей пробует только мягкий `BX24.placement.call("reloadData")`, если команда доступна;
- worker запоминает последнюю открытую сделку в `dealInvoiceSummaryLastSeenDeal`;
- на каждом цикле заново читает контекст через `BX24.placement.info()` и `PLACEMENT_OPTIONS.URI`;
- на kanban URL раз в 15 секунд приоритетно проверяет последнюю сделку через `crm.deal.get`;
- при изменениях запускает обычный serverless-пересчёт с диагностикой `background-kanban-return-recalculate`;
- если последняя сделка неизвестна, остаётся fallback через `crm.deal.list` по `DATE_MODIFY DESC`.

Для Marketplace-заявки указывай только `CRM`, `Встраивание приложений` и `Пользователи (минимальный) / user_brief`: `user_brief` нужен только для `user.get`, чтобы показывать ФИО ответственных по счетам. `Пользователи (базовый) / user_basic`, полный `Пользователи / user`, `Пользовательские поля пользователя / user.userfield` и отдельный `Базовый / basic` не запрашивать.

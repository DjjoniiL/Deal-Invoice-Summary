# План адаптации для Bitrix24 Marketplace

## Цель

Подготовить отдельный zip-архив статического приложения для загрузки в Bitrix24 Marketplace без собственной серверной части. Документация, тесты, исходная серверная версия и служебные файлы остаются в репозитории, но не попадают в Marketplace zip.

## Текущий статус

На 2026-08-10 serverless-адаптация подготовлена в папке `marketplace/` и проверяется на тестовом портале `https://vibecod1.bitrix24.ru`. Последний локальный архив для загрузки: `Калькулятор счетов Marketplace v10-8.zip` (`layout-20260810-10`).

Что уже перенесено в Marketplace-версию:

- финальный дизайн основного экрана из серверной версии;
- пункт левого меню через `LEFT_MENU`;
- создание стандартных пользовательских полей сделки;
- отображение человекочитаемых названий полей вместо символьных кодов;
- сохранение сопоставления через `app.option.*`;
- попытка автоматического добавления раздела `Расчёт оплаты счетов` в карточку сделки при `Создать автоматически` и `Сохранить сопоставление`;
- настройка раздела карточки сделки по доступным воронкам через `crm.category.list` и `extras.dealCategoryId`, потому что в Bitrix24 раскладки карточек сделок зависят от воронки;
- fallback для ответа `Card layout is empty`: Marketplace-версия создаёт безопасную дефолтную раскладку и добавляет в неё раздел `Расчёт оплаты счетов`;
- ручной пересчёт по ID или ссылке сделки;
- человекочитаемые названия стадий счетов через `crm.status.list` по `SMART_INVOICE_STAGE_*` для новых счетов Bitrix24; если `crm.status.list` возвращает короткий `STATUS_ID`, приложение собирает полный ключ из `ENTITY_ID` и `STATUS_ID`, а также диагностирует справочник через `crm.status.entity.types`;
- ФИО ответственных в таблице счетов через `user.get` и нормализацию ID пользователей;
- даты выставления и сроки оплаты в таблице и CSV-отчёте в формате `ДД.ММ.ГГГГ` без времени;
- накопительный установочный журнал с timestamp и 4-секундной паузой перед завершением установки;
- ручной массовый пересчёт всех сделок со счетами в выбранном окне 42/28/21/14/7/2 суток с прогрессом и формированием CSV-отчёта за период;
- окно заявки на серверную версию при выборе режимов `Утром и вечером` или `Постоянный`; окно не показывается, если портал уже имеет серверный флаг в `app.option`;
- режим `Ручной`, в котором массовый пересчёт и текущие ручные функции доступны без серверного окна;
- поле `Расписание` в блоке `Автопересчёт`: `по кнопке` для ручного режима, `09:44, 18:44` для режима утром/вечером, `08:30, 10:30, 12:30, 14:30, 16:30, 18:30, 20:30` для постоянного режима;
- автоматический возврат режима на `Ручной` при закрытии окна заказа серверной версии без серверного флага;
- ориентировочный расход micro-сервера в справке серверных режимов за 30 рабочих дней: `164,2 Ꝟ` для `Постоянный` и `139,8 Ꝟ` для `Утром и вечером`;
- CSV-отчёт в браузере по кнопке `Скачать отчёт` после формирования;
- cache-busting ассетов `layout-20260810-10` и расширенный журнал ошибок.

## Состав Marketplace zip

- `install.html` — обязательный установщик приложения.
- `install.js` — логика установки: накопительный журнал, `placement.bind` только для `LEFT_MENU` и `BX24.installFinish()`.
- `install.css` — стили установщика.
- `index.html` — основной экран приложения и вкладка сделки.
- `app.js` — расчёт, создание полей, сохранение настроек и вызовы REST через `BX24.callMethod`.
- `style.css` — стили приложения.

## Перенос логики

1. Заменить серверные VibeCode API-вызовы на прямые Bitrix24 REST-вызовы из iframe:
   - `crm.deal.get`;
   - `crm.deal.update`;
   - `crm.deal.fields`;
   - `crm.deal.userfield.list`;
   - `crm.deal.userfield.add`;
   - `crm.item.list` с `entityTypeId=31`;
   - `crm.status.list` для справочника стадий новых счетов `SMART_INVOICE_STAGE_*`;
   - `user.get` для ФИО ответственных.
2. Хранить настройки маппинга через `app.option.*`, с fallback в `localStorage` для dev-установки.
3. Считать суммы только по текущему списку счетов, полученному из Bitrix24; удалённые счета не учитываются, потому что `crm.item.list` их не возвращает.
4. Оставить CSV-экспорт в браузере через `Blob`.

## Ограничения serverless-версии

Статический zip без сервера не может принимать POST-запросы от Bitrix24, поэтому в нём нет настоящего фонового push-обработчика событий. Автоматический пересчёт по событиям остаётся функцией VibeCode/серверной версии. Marketplace-вариант пересчитывает данные при открытии карточки и по ручной кнопке.

## Проверка перед упаковкой

1. `npm run lint`
2. `npm test`
3. Собрать новый Marketplace zip только из файлов папки `marketplace/`; для каждого крупного изменения использовать новое имя с номером версии или commit short SHA. Не обновлять старый безымянный zip и не собирать архив с серверной версией.
4. Установить архив на тестовом портале через developer console.
5. В developer console для версии приложения включить добавление основной страницы приложения в левое меню и указать название пункта меню `Расчёт оплаты счетов`. Это делается настройкой версии/описания приложения, а не `placement.bind`, чтобы Bitrix24 открывал приложение как основной iframe/слайдер.
6. Проверить, что `LEFT_MENU` появился после установки. Вкладку сделки настроить в developer console. Не вызывать `placement.bind` для `CRM_DEAL_DETAIL_TAB` из `install.js`: install token Marketplace-архива может не иметь нужных прав.
7. Проверить внешний вид: Marketplace-версия должна повторять утверждённый основной экран серверной версии, а не использовать отдельный упрощённый шаблон.
8. Проверить создание полей, сопоставление, вкладку сделки и ручной пересчёт.

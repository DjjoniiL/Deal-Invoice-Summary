## Правило по дизайну

Визуальная часть основного экрана утверждена как финальная. Подробное описание лежит в `DESIGN_GUIDE.md`.

Без отдельного подтверждения пользователя не менять:

- `public/menu.css`;
- визуальную композицию `public/index.html`;
- размеры, цвета, отступы, сетку, порядок блоков и внешний вид элементов основного экрана.

Дальше работаем только над логикой индекса, backend/API, установочным сценарием, переносом на новый сервер/портал и OAuth/push-интеграцией. `public/app.js` можно менять для логики и API-вызовов, но не для изменения утверждённого визуального поведения.

- Финальный дизайн основного экрана утверждён и описан в `DESIGN_GUIDE.md`.

## Важные настройки

Файл `data/settings.json`:

```json
{
  "includeNegativeStages": false,
  "issuedField": "ufCrmInvSumIssued",
  "paidField": "ufCrmInvSumPaid",
  "unpaidField": "ufCrmInvSumUnpaid",
  "remainingField": "ufCrmInvSumRemaining",
  "autoRecalcMode": "twiceDaily"
}
```

В production env обязательно передавать:

- `NODE_ENV=production`
- `VIBE_API_BASE_URL=https://vibecode.bitrix24.tech`
- `VIBE_API_KEY=<актуальный VibeCode API key>`
- `AUTO_RECALC_ENABLED=true`
- `AUTO_RECALC_INTERVAL_MS=420000`
- `AUTO_RECALC_RECENT_HOURS=504`

Без `VIBE_API_KEY` backend API вернёт ошибку `VIBE_API_KEY is not configured`.

## Git

Перед пушем:

```powershell
git status --short
npm run lint
npm test
```

Важное правило: push в GitHub выполняется только после того, как локальные правки загружены на портал, проверены пользователем вручную и пользователь отдельно подтвердил push. Пока пользователь не подтвердил проверку на портале, push не делать.

После каждого крупного изменения Marketplace-версии собирать новый архив только для безсерверной версии с номером версии или commit short SHA в имени. Серверные архивы больше не создавать. Безымянный `Калькулятор счетов Marketplace.zip` не обновлять; архивы, которые уже отдавались на проверку или загружались на портал, не перезаписывать.

Для Marketplace zip `install.js` может вызывать `placement.bind` только для `LEFT_MENU`. `CRM_DEAL_DETAIL_TAB` через install token возвращал `The request requires higher privileges than provided by the access token`, поэтому вкладку карточки сделки настраивать в developer console в карточке приложения/версии.

После изменений:

```powershell
git add .
git commit -m "Release MVP v1"
git push
```

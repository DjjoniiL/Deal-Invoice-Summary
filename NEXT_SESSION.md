# Следующая сессия

## Текущее состояние

Проект доведён до MVP v1. Основная версия приложения работает на новом VibeCode сервере:

- Server ID: `c576798a-ec5f-4491-b6a2-b28e74fc445f`
- URL: `https://app-2657fd62db74.vibecode.bitrix24.tech`
- Основной экран левого меню: `/`
- Совместимый маршрут вкладки сделки: `/deal-tab`
- Runtime: `node20`
- Start command: `cd /opt/app && node src/server.js`
- Internal port: `3000`

Marketplace-адаптация готова как serverless-версия v35 в папке `marketplace/`. Она не использует VibeCode backend, загружается на портал zip-архивом и работает через Bitrix24 JS SDK/REST из iframe. Локальный архив для загрузки: `Калькулятор счетов Marketplace v35.zip`. Runtime/cache marker: `layout-20260826-1`; в видимом интерфейсе, установочном журнале и диагностике показывать `Deal Invoice Summary v.35 Marketplace B24`.

Marketplace v18: в блоке `Сопоставление полей сделки` кнопка настроек перенесена в нижнюю строку действий и открывает `settings.html`. На странице настроек выбираются воронка расчёта и период массового пересчёта; список воронок кэшируется при установке через `crm.category.list` и может обновляться из настроек. В блоке `Массовый пересчёт сделок` показывается выбранная воронка. Сводка массового пересчёта хранится в памяти открытой страницы до закрытия приложения и сбрасывается при смене периода или воронки. Диаграмма статистики периода переведена с SVG на canvas. Левый блок сопоставления полей расширен, правый блок массового пересчёта расширен и центрируется в пустом состоянии. Пользовательские поля отображаются по названиям Bitrix24 с расширенным поиском label/title-полей, а открытая линия загружается только на странице настроек. Установщик очищает накопленные `LEFT_MENU`-привязки циклом до `count: 0`, пере-привязывает `PAGE_BACKGROUND_WORKER` при ошибке лимита placement и использует задержку 2.5 секунды. Массовая статистика берёт сделки через `crm.deal.list`, включает сделки без счетов и сделки в работе; создание и сохранение сопоставления не сбрасывают воронку и период.

Marketplace v19: установщик создаёт стандартные поля и дефолтное сопоставление для всех пользователей через `app.option`, добавляет раздел карточки сделки во все доступные воронки, включая основную, и кэширует воронки с обязательной категорией `0`. Блок выбора полей для сопоставления закрыт для не-администраторов через `user.admin`; сохранение и создание полей дополнительно проверяют права в обработчиках. В выпадающих списках больше нет fallback на `UF_CRM_*`/символьные коды: если Bitrix24 не вернул человекочитаемое имя, показывается нейтральное `Поле сделки N`.

Marketplace v20: сотрудники без админки могут открывать `settings.html` и сохранять выбранную воронку/период расчёта; ограничение прав касается только сопоставления полей. Worker на страницах CRM-сделок/канбана делает baseline последних изменённых сделок через `crm.deal.list` по `DATE_MODIFY` и при изменении `STAGE_ID`/суммы запускает пересчёт без backend. Установщик больше не делает `placement.bind` для `LEFT_MENU`, только очищает старые привязки, чтобы убрать дубли; основной пункт левого меню должен быть настроен в версии Marketplace. Низ блока сопоставления переведён на устойчивую сетку действий, чтобы статус и кнопка настроек не срезались.

Marketplace v21: выбор воронки и периода расчёта сохраняется локально для пользователя через `dealInvoiceSummaryUserCalculationSettings`, поэтому сотрудник без админки не получает ошибку `Administrator authorization required` при сохранении этих двух настроек. По умолчанию выбраны все воронки и период `1 мес`; список периодов ограничен значениями `1 мес`, `3 мес`, `6 мес`. Перед массовым расчётом показывается подтверждение с количеством сделок за период и оценкой времени с шагом 5 минут; `НЕТ` закрывает окно без изменений, `ДА` запускает расчёт. Страница настроек получила отдельную сетку действий, чтобы статус сохранения не ломал фронт.

## Важные настройки

Файл `data/settings.json`:

```json
{
  "includeNegativeStages": false,
  "issuedField": "ufCrmInvSumIssued",
  "paidField": "ufCrmInvSumPaid",
  "unpaidField": "ufCrm_1785930142",
  "remainingField": "ufCrmInvSumRemaining",
  "autoRecalcMode": "twiceDaily"
}
```

В production env обязательно передавать:

- `NODE_ENV=production`
- `VIBE_API_BASE_URL=https://vibecode.bitrix24.tech`
- `VIBE_API_KEY=<актуальный VibeCode API key>`
- `AUTO_RECALC_ENABLED=true`
- `AUTO_RECALC_INTERVAL_MS=420000`
- `AUTO_RECALC_RECENT_HOURS=504`

Без `VIBE_API_KEY` backend API вернёт ошибку `VIBE_API_KEY is not configured`.

## Git

Перед пушем:

```powershell
git status --short
npm run lint
npm test
```

Важное правило: push в GitHub выполняется только после того, как локальные правки загружены на портал, проверены пользователем вручную и пользователь отдельно подтвердил push. Пока пользователь не подтвердил проверку на портале, push не делать.

Важное правило для генерации Word-файлов: не использовать Microsoft Word COM automation (`New-Object -ComObject Word.Application`) и невидимый запуск Word для создания `.docx`. Этот метод уже зависал в рабочей сессии и оставлял процесс `WINWORD`. Для `.docx` использовать прямую сборку OpenXML zip-пакета, проверенную библиотеку или внешний конвертер вроде `pandoc`, если он установлен. При прямой сборке учитывать ошибки этой сессии: Windows PowerShell 5 требует UTF-8 с BOM для кириллицы в `.ps1`; для zip-пакета `.docx` нужны прямые `/` в entry paths; перед `[System.IO.Compression.ZipArchiveMode]` загрузить `System.IO.Compression`; если старый `.docx` заблокирован, писать новый versioned/final файл и не зависать на перезаписи.

Локальные коммиты по обычному рабочему ритму делать после каждого третьего существенного изменения, чтобы история не дробилась слишком мелко. Если пользователь в конкретной сессии явно требует commit в обязательном цикле изменений, выполнить commit в конце этого цикла.

После каждого крупного изменения Marketplace-версии собирать новый архив только для безсерверной версии с номером версии или commit short SHA в имени. Серверные архивы больше не создавать. Безымянный `Калькулятор счетов Marketplace.zip` не обновлять; архивы, которые уже отдавались на проверку или загружались на портал, не перезаписывать.

Для Marketplace zip `install.js` не должен создавать `LEFT_MENU` через `placement.bind`: основной пункт левого меню задаётся настройкой версии Marketplace, а runtime-привязки `LEFT_MENU` установщик только очищает. `CRM_DEAL_DETAIL_TAB` через install token возвращал `The request requires higher privileges than provided by the access token`, поэтому вкладку карточки сделки настраивать в developer console в карточке приложения/версии.

После изменений:

```powershell
git add .
git commit -m "Release MVP v1"
git push
```

## Очередность работ по автопересчёту

Доводим Marketplace serverless-версию без собственного backend:

- режимы без сервера должны оставаться честно serverless;
- основной автоматический сценарий без сервера — пересчёт при открытии карточки сделки и worker-проверка уже открытой страницы;
- ручной пересчёт и массовый пересчёт по окну остаются внутри Marketplace через Bitrix24 JS SDK/REST;
- внешние обработчики, OAuth-секреты, API-ключи, Beget/VibeCode вызовы и серверные архивы в текущий Marketplace-пакет не добавлять.

План serverless-доработки:

1. Добавить режим `При открытии сделки`. Реализовано в `layout-20260812-1`.
2. При открытии карточки получать ID сделки из `PLACEMENT_OPTIONS`.
3. Читать сделку через `crm.deal.get` и связанные счета через `crm.item.list` с `entityTypeId=31` и `parentId2 = dealId`.
4. Считать суммы и обновлять поля сделки через `crm.deal.update`, только если значения отличаются. Реализовано в `layout-20260812-1`.
5. Убрать пункт `Ручной` из списка режимов, но сохранить ручной и массовый пересчёт по окну как действия по кнопке. Реализовано в `layout-20260812-2`.
6. В открытой карточке повторять пересчёт при изменении суммы или стадии сделки. Усилено через `PAGE_BACKGROUND_WORKER` в `layout-20260812-4`.
7. Режим `При изменении сделки/счёта` в Marketplace работает через `PAGE_BACKGROUND_WORKER` на открытых страницах портала.

Beget не использовать для режимов `Постоянный` и `Утром и вечером`; для текущей задачи он не рассматривается.
